## Overlay GLES self-test — RESOLVED + DEVICE-VERIFIED (2026-06-25)

The 117HD debug overlays were not GLES-portable on strict-ES drivers (a `const int → float` artifact, plus a
`vec2`/`ivec2` mismatch found below). They are **dev-toggle / feature gated**, so they never compile in a default
login run — and `rlhd_shaderdump` only *logs* the downported source, it activates nothing. So the matrix's `rlhd`
leg never actually exercised them until this run. A purpose-built **overlay self-test** closes that gap:
`MobileUiBridge.rlhdOverlaySelfTest` type-scans `HdPlugin`'s `ShaderOverlay` fields and force-`setActive(true)`s
each (→ `initialize()` → `shader.compile()` on the live driver). Armed by a pushed `rlhd_overlay_selftest` marker
via `FB_OVERLAY_SELFTEST=1`; the gate asserts `found≥3 && activated==found` so a no-op self-test can't pass on
"no ShaderException". Each overlay program also compiles the shared `overlay_vert.glsl`, covering all four
reachable overlay shaders (`overlay_frag.glsl` is replaced per-stage by every subclass → never compiled).

**Self-test result across the full matrix: every device that reached `isGpu` logged `RLHD_OVERLAY_SELFTEST
found=3 activated=3`, `shaderErrors=0`** — Mali-G715 (shiba/husky/akita/comet), Mali-G78 (bluejay),
Adreno-740 (dm1q/b5q/XQ-DQ72), Adreno-750 (e3q) = 9 devices, 4 driver families. Only `gta8wifi` (Mali-G52)
didn't capture the self-test line (the coverage gap above); a longer-`FB_TIMEOUT` re-run is tracked.

- **The pre-fix Mali run caught a real bug the static int→float port could not:** `0:194 Type mismatch in
  arithmetic operation between 'vec2' and 'ivec2'`. `tiledLightingResolution`/`sceneResolution` are `ivec2`
  uniforms, so `fUv * tiledLightingResolution` is a `vec2×ivec2` op strict ES rejects. Fixed by wrapping each in
  `vec2(...)` (commit `89997d6cbe`). The overlay had **never** compiled on-device (tiled-lighting is
  force-disabled on Android), so only the forced self-test exposed it.
- **Dead-path twin — SOURCE HYGIENE only, NOT functional coverage:** the same `vec2×ivec2` pattern (plus
  `int(ceil(pointLightsCount/32.0))` and `uvec4(0.0)`) lived in production `tiled_lighting_frag.glsl` (line 64
  et al.). Now made strict-ES-clean via a layered shader-overlay override (commit `6d7c9442fa`) mirroring the
  iOS gpu-zone port. **Status = Verified-Compiling-by-mirror, NOT Verified-Working:** the path stays
  force-disabled on Android (`RLHDStarter` sets `tiledLighting=false`), this override has not been compiled on an
  Android device (the overlay self-test exercises only `ShaderOverlay` subclasses, not this production program),
  and it is unexercised at runtime. It removes a latent strict-ES landmine if the feature is ever enabled — it
  does not add functional coverage. Pristine rlhd-src untouched; logic identical (only type casts; insertion-sort
  body verbatim upstream).
- Reproduce a device: `FB_DEVICE=<model> FB_VERSION=<api> FB_OVERLAY_SELFTEST=1 ./fb-gate.sh rlhd`. Harness:
  commits `eba702be54` (self-test) + `e98c316440` (type-scan + gate coverage assertion). Shader ports:
  `c346ba988b` / `d489792b8e` / `89997d6cbe` (overlays) + `6d7c9442fa` (production twin).
