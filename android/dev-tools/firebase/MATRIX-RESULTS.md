## Read

- **5/5 PASS.** The GLES caps gate (`probeGpuCaps`-equivalent ES3 context-create + base-gpu shader compile)
  is green on **real Mali (G715 new, G78 old) and Adreno (740)** silicon across **Android 12 / 14 / 15**
  (api 32 / 34 / 35), in both portrait and landscape (the Xperia cutout-landscape axis).
- **esTier = 32 (GLES 3.2) on every device** → all five satisfy the auto-GPU promotion bar, so a fresh
  install on any of them would caps-probe to an accelerated renderer rather than the CPU fallback. No device
  reported a lower tier or a context-create failure (which is exactly what the caps gate exists to catch).
- Per-device gating record: each row's VERDICT is reproducible by re-running
  `FB_DEVICE=<model> FB_VERSION=<api> ./fb-gate.sh recon`.

## Coverage vs the audit matrix (what this smoke tier does and does NOT cover)

Covered: **Mali new + Mali old + Adreno** × **api 32/34/35** × **phone + cutout-landscape**. Not covered by
this 5-device smoke (deliberately, to fit the Spark free quota):

- **GPU vendors PowerVR + Xclipse** — PowerVR is essentially absent from the Test Lab catalog; Xclipse needs
  a region-specific Exynos variant. Best-effort only; revisit if a device surfaces.

  Galaxy Tab A8), not run here.
- **Heavier modes `rlhd` (117HD) + `gpu`** — this smoke gates the caps tier only; the 117HD-on-real-driver
  proof stands on GATE row 2 (Pixel 7a / Mali-G710 in-world) until a `--modes recon,rlhd` matrix is run.
- **Older OS (Android 9/12 = api 28/31)** — scarce as physical devices; api 32 (bluejay) is the floor here.
- **TV** — no physical TV device exists in Test Lab; the TV path is handled by the COMPAT-03 scope-out
  (release drops `LEANBACK_LAUNCHER`), not a matrix cell.
