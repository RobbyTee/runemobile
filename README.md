# RuneLite on mobile (unofficial)

> **Unofficial fan project. Not affiliated with, endorsed by, or sponsored by
> Jagex or RuneLite.** This is a sideload-only, personal/technical build. It is
> **not** on Jagex's approved-client list — using it on a live account carries a
> real risk of a ban. **Use a throwaway account, at your own risk.** Not
> available on the App Store, Google Play, or F-Droid.

A native mobile app that runs **real, unmodified RuneLite** — including the full
plugin ecosystem — on an **in-process, on-device OpenJDK 21**. No streaming, no
host machine: the actual RuneLite client executes on the phone inside a second
JVM, and a thin native shell presents it with touch controls and mobile chrome.

## What it is

- The mobile process (Android ART / iOS) hosts a **second HotSpot JVM**: C++
  `dlopen`s the embedded `libjvm.so` and calls `JNI_CreateJavaVM`, then boots
  stock RuneLite headless. A [Caciocavallo](https://github.com/caciocavallosilano/cacio)
  AWT backend drives the engine's `Canvas`/`BufferProvider` off-screen.
- A shared Java bridge under `runelite-client/.../headless/` exposes the engine
  to the native shell; it is shared **verbatim** between the Android (Kotlin /
  Jetpack Compose) and iOS (Swift / UIKit) shells.
- Three renderers, selectable in the plugin panel: **CPU** (software),
  **GPU** (the RuneLite GPU plugin), and **117HD**. Accelerated renderers are
  auto-promoted only after a live GPU capability probe, and fall back to CPU.
- The unmodified RuneLite plugin ecosystem runs as-is.

## Status & devices

- **Android:** arm64-v8a only · `minSdk 28` / `target 35`. Verified on a Pixel 7a
  (Mali-G710) and the arm64 emulator, including a genuine 16 KB-page kernel.
- **iOS:** runs on-device via a per-launch JIT debugger attach (see the iOS
  notes); the embedded JVM and shared bridge are the same family as Android.

## Install (sideload)

Signed builds are published on the Releases page. There is no store
distribution. First launch requires you to sign in to your (throwaway) Jagex
account on-device; no credentials or tokens ship in the app.

## Build from source

A fresh clone does **not** contain the embedded JRE or the client jars — they are
gitignored and regenerated by tracked, SHA-pinned staging scripts. The two app
native libraries (`libhelloshell.so`, `librlawt.so`) are **not** staged; they are
built automatically by Gradle/CMake from tracked C++ source.

From the repository root, in order:

```sh
tools/stage-android-jre.sh                       # SHA-pinned arm64 OpenJDK 21 -> jniLibs + assets/jvm/jre
android/dev-tools/gpu/stage-android-gpu-jar.sh    # -> client-*-gpu.jar   (run BEFORE the runtime stage so
android/dev-tools/gpu/stage-rlhd-zone-jar.sh      # -> client-*-rlhd.jar     their SHAs fold into runtime.tag)
tools/stage-mobile-runtime.sh --android-only      # gradle :client:shadowJar -> client-*-shaded.jar + probes.jar
cd android && ./gradlew :app:assembleRelease      # never bare `assemble` (that also builds the :recon probe app)
```

> The GPU and 117HD jars (steps 2–3) are required: omitting them produces an
> un-bootable APK. The embedded JDK is fetched from a single third-party host at a
> pinned SHA — mirror it if you depend on reproducible builds.

## Architecture

```
 ART / iOS process
   └─ native shell (Kotlin+Compose / Swift+UIKit) ── SurfaceView/CAEAGL host
        └─ C++ bootstrap: dlopen libjvm.so → JNI_CreateJavaVM
             └─ embedded OpenJDK 21 (HotSpot, JIT)
                  └─ stock RuneLite (headless) + Caciocavallo AWT
                       └─ headless/* bridge ──► shared verbatim with the other port
```

The native UI thread is **never** attached to the embedded JVM. R8/minification
is intentionally off.
